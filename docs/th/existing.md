# วาดระบบที่มีอยู่แล้ว

Walkboard ไม่ได้วาดแค่งานใหม่ แต่วาด infrastructure ที่คุณรันอยู่แล้วได้ด้วย ถ้าใน repository มีไฟล์ที่บอกว่าระบบหน้าตาเป็นยังไง เช่น Terraform, Kubernetes manifest หรือ Compose file agent จะอ่านไฟล์เหล่านั้นแล้ววาดออกมาเป็น [map](pictures/map.md) ที่บอกว่าอะไรอยู่ข้างในอะไร และอะไรต่อกับอะไร

หน้านี้อธิบายวิธีขอ map ตรวจว่าถูกไหม แล้วใช้มันวางแผนการแก้ไข

## ขอ map

เปิด Claude Code ใน repository แล้วบอกว่าอยากดูอะไร และอธิบายไว้ในไฟล์ไหน เช่น

```
/walkboard explain our AWS network from the Terraform in infra/
/walkboard draw the Kubernetes setup in deploy/
```

จะพิมพ์เป็นภาษาไทยก็ได้ เช่น "อธิบาย network บน AWS จาก Terraform ใน folder infra/"

agent จะทำงานใน [โหมดอธิบาย](modes/explain.md) อ่านไฟล์ แล้ววาด account, network, cluster และ service ที่เจอ กล่องไหนที่มาจากไฟล์จะชี้ไปที่ไฟล์และบรรทัดที่ประกาศมันไว้ คลิกแล้วจะเห็นโค้ดเลย

## ตรวจส่วนที่ agent หาไม่เจอ

ไฟล์มักไม่ได้เล่าทุกอย่าง security group อาจถูกจัดการจากที่อื่น หรือ service บางตัวอาจ config ด้วยมือ ถ้า agent หาอะไรใน repository ไม่เจอ มันจะไม่แอบเติมเอง แต่จะวาดกล่องนั้นเป็นเส้นประพร้อม ❓ ให้คุณเห็นว่าตรงไหนเป็นการเดา

ถ้าจะตอบเรื่องที่ agent เดาไว้ กด **✎ ตอบ** แล้วบอกว่าความจริงเป็นยังไง ถ้าภาพผิดแบบอื่น บอก agent ในแชทได้เลย เช่น "database อยู่ใน data subnet ไม่ใช่ app subnet"

> **ควรรู้:** โหมดอธิบายไม่แก้อะไรในโปรเจกต์ของคุณเลย map แสดงสิ่งที่ไฟล์บอก ซึ่งอาจไม่ตรงกับที่รันอยู่จริงทุกอย่าง ถ้าอยากให้ agent ดู cloud account จริงด้วย ให้ขอเทียบแบบสำหรับการแก้ไขครั้งถัดไป ใน [โหมดออกแบบ](modes/design.md) agent อาจเช็กว่ามีอะไรอยู่จริงบ้าง โดยใช้แค่คำสั่งที่อ่านอย่างเดียว และถามคุณก่อนทุกครั้ง

## วางแผนการแก้ไขบน map

พอ map ถูกต้องแล้ว ก็ใช้มันวางแผนงานต่อไปได้ ทำได้สองแบบ

- **ขอเป็นคำพูด** เช่น "วางแผนเพิ่ม read replica ให้ database ของ orders" agent จะเริ่ม[แผน](modes/plan.md)สำหรับการแก้ไขนั้น
- **วาดเอง** กด **✎ ร่างการแก้ไข** แล้ว[ร่างการแก้ไขเอง](draft.md) จากนั้นกด **ให้ agent รีวิวภาพนี้**
